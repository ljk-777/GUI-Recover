# GUI-Recover 0.2.0rc1 发布候选

GUI-Recover 为 MiniWoB 上的视觉 GUI Agent 提供可重复的故障注入、有限恢复、轨迹记录和评测。恢复策略从截图和已提议动作判断是否等待或重试。BrowserGym 的精确终止奖励用于评价完整任务。

## 从安装到验收

1. 在 Python 3.11 环境安装项目，在源码或源码包目录运行 `bash scripts/setup_miniwob.sh` 和 `python -m playwright install chromium`。Ubuntu 系统库安装方式见 [README](../README.md#安装与本地验收)。
2. 运行 [CPU 演示](../README.md#安装与本地验收) 验证浏览器重置、执行、轨迹和回放。该演示用有权限的诊断 oracle，预期三条简单点击均成功。
3. 用一张支持 BF16 的 CUDA 卡和本地固定版 ShowUI-2B，运行 [GPU 最小恢复演示](../README.md#gpu-最小恢复演示)。`gui-recover text-recovery` 跑七种条件和两种策略，`gui-recover audit-text-recovery` 从输出目录复核。正式留出集复现使用事先登记的布局清单和排除历史数据的配置。

## 留出评测

| 任务与分母 | 基线 | 候选策略 | 成对变化 |
|---|---:|---:|---|
| 原始 click-button、click-dialog、click-tab，共 12 个布局 | 6/12 | 11/12 | 新增 5，回退 0 |
| Enter Text 的漏输入，共 4 个布局 | 0/4 | 4/4 | 新增 4，回退 0 |
| Enter Text 的三类可见文字错误，每类 6 个布局 | 0/18 | 18/18 | 新增 18，回退 0 |
| 同批 6 个布局的正常输入 | 6/6 | 6/6 | 零重输 |
| 同批 6 个布局的末尾空格 | 0/6 | 0/6 | 截图逐对相同，精确提交失败 |

前两行使用继续策略对比视觉触发的固定裁剪重试。在第一行的 12 个点击布局和另外 4 个正常输入布局上，视觉策略共使用 26 次逻辑模型请求、6 次重试。继续策略使用 20 次请求，无条件固定裁剪使用 30 次请求、10 次重试。四种任务的对照与成本见 [预强化学习实验](PRE_RL_RECOVERY.md#正式结果)。

后三行取自独立的输入研究，两套策略共用替换执行器和等待预算。字形核验每修复一个可见错误多一次定位，末尾空格保留在分母内。6 个布局分别复用于七种条件。该组与前两行使用不同的基线和布局，效果按各自实验报告。见 [视觉文本核验](VISUAL_TEXT_CONTENT.md#正式结果)。

## 学习接口

- SFT 已在固定底座上完成真实轨迹采集、按场景切分、LoRA 更新、独立重载和浏览器执行。补充实验使用 108 条训练、38 条验证和 79 条测试监督对，两个 adapter 各运行 128 步。条件纠错有局部改善，也测到正常任务回退。发布候选默认使用冻结的 ShowUI。见 [SFT 数据与对照](SFT_RECOVERY.md)。
- `RecoveryDecisionEnv` 提供有限动作空间、动作掩码与精确终止奖励。真实轨迹读取器校验训练与验证索引、截图以及转移，训练读取拒绝测试集。CPU 离线 Q 实验从 54 条真实训练轨迹拟合策略，留出集上和人工先等规则同为正常、漏输入、延迟输入各 4/4。见 [环境接口](PRE_RL_RECOVERY.md#interface-and-reward) 和 [离线 Q 结果](RECOVERY_OFFLINE_RL.md#正式结果)。

## 适用范围

结果来自固定 MiniWoB 任务、小规模布局和有限动作预算。字形核验面向 Chromium 固定视口中的初始空白白底输入框和短 ASCII 文字。自主多步导航、跨站点推广和不可见字符需要单独验证。底座权重、训练数据全集和服务器配置由各自来源管理，发布包提供代码、协议、统计和经过核验的示例。

## 发布候选验收

- 在空白 Python 3.11 环境安装 wheel，运行 CPU 诊断，3/3 成功并生成 HTML 回放。安装后的审计命令复核了原来 84 条正式轨迹，结果与源码版逐字节一致。
- 在 RTX 4090 D 的 12032 MiB 配额内，从单独安装的同一 wheel 跑完 14 条默认示范轨迹。CPU 审计复核了 32 个决策和 46 张分支内截图。
- 从安装包重新核验 SFT 的场景与图片切分、adapter 更新和重载记录，以及 110 条预 RL 轨迹。离线 Q 结果从真实训练转移重算，测试截图与训练决策截图无重叠。

源码包和 wheel 均通过分发检查。自动化结果见 [GitHub CI](https://github.com/ljk-777/GUI-Recover/actions/runs/44670989450)。

## 0.2.0rc2 扩展

发布候选增加 `gui-recover active-text-recovery` 和 `gui-recover audit-active-text-recovery`。前者运行字形、立即重输和主动探测三路对照，后者从磁盘核验相同布局、恢复决策、选区截图和精确奖励。新命令可从安装包直接执行。正式证据和当前适用范围见 [主动核验报告](ACTIVE_TEXT_VERIFICATION.md)。

主动规则在四个留出布局的七种条件上达到 28/28，正常输入零重输。它与立即重输成功数相同，少重输 8 次，多做 20 次浏览器操作。随后训练了何时探测的在线策略。该策略保留了常规组 14/14 的成功，少探测两次，但两条延迟尾空格挑战均失败。主动规则在挑战组 2/2 成功，因此 RC2 的演示使用主动规则。见 [学习策略和挑战对照](LEARNED_ACTIVE_PROBE.md)。

同一 RC2 wheel 分别在全新 Mac Python 环境和 Linux 单卡环境验收。Mac 上 CPU 诊断 3/3 成功，两个安装后审计命令分别复核既有的 84 条版本 1 和 84 条版本 2 轨迹。Linux 上安装后的主动演示完成 21 条轨迹，复核了 49 个决策、69 次浏览器操作和 76 张分支内截图。[RC2 自动化检查](https://github.com/ljk-777/GUI-Recover/actions/runs/44685082310)

## 0.2.0rc3 验收

- 新命令 `gui-recover demo-tail-probe` 在 macOS 和 Linux 上用同一安装包分别通过 24 条精确提交。每个平台的 12 条正常输入零重输，8 个负例全部停止修复。演示只需要 CPU 和 Chromium。
- 四个独立 MiniWoB 布局上的配对计时共 56 条轨迹。合并探测的两个按键与中间截图后，28 对结果和视觉证据保持一致。实际探测的 12 对中位耗时降低 33.8%，达到预登记的 30% 门槛。
- 新增 `enter-text-2` 和 `enter-text-dynamic` 任务。RTX 4090 D 上同一 wheel 跑完 72 条轨迹，主动核验 24/24，字形基线 20/24，无条件重输 24/24。相对无条件重输，主动核验少重输 8 次，多做 8 次 BrowserGym 操作。采样峰值 5309 MiB。
- Mac 全量测试 143 项通过。Ubuntu 22.04、24.04 和分发包检查通过。安装后的 CPU 审计重算原生任务迁移的 72 条轨迹，且与旧的两个版本各 84 条轨迹的审计结果逐字节相同。

参见[实验协议与复现命令](TAIL_PROBE_PORTABILITY.md)、[结构化结果](../examples/rc3-tail-validation.json)和 [RC3 自动化检查](https://github.com/ljk-777/GUI-Recover/actions/runs/44690409419)。
